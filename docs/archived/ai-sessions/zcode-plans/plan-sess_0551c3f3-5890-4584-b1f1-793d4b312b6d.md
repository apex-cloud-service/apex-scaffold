探查确认的承重事实：
- 网关 `GatewayJwtVerifierService` **已支持 RSA+kid 双算法**（`keyCache` 按 kid 精确匹配 + `hmac-legacy` HMAC 回退）——A1 网关零代码改动；
- file-service 的 `IdentityRelayAuthenticationFilter` 已支持多公钥 kid（`file.security.jwt-public-keys-base64`），workflow/office 为单钥旧版，对齐即可；
- 真正缺口：apex-system `JwtAuthenticationFilter` L244 静态调用 `JwtUtil.parseToken`（仅 HS256 `Keys.hmacShaKeyFor`），无公钥注入通道；
- 认证中心登录令牌已全部走 `JwtKeyMaterialService`（sign 带 kid header / parse 按 kid 选钥 / `availablePublicKeys()` 返回 `Mono<Map<String,PublicKey>>`）；未统一的只有 `OAuth2Service.jwt()`（L421-437，用 `OAuth2Properties` 静态钥）与 `OAuth2MetadataService.jwks()`（单键投影）；
- `config/nacos/apex-common.yaml` L33-39 已预留 `apex.jwks.endpoint/remote-url/refresh-interval-seconds` 公共约定，apex-common 尚无实现——共享 JWKS 客户端对齐此命名落位；
- apex-common 已依赖 webflux/jjwt 0.12.6/reactor-test，共享组件可落位；`JwtKeyMaterialService.sign(subject, claims, expireMillis)` 透传 claims map（iss/aud/scope 可经 claims 携带，切换无需扩 API）。

## 改动内容

### A1 双算法验签统一
1. **apex-common 新增 `common/security/JwtMultiKeyVerifier`**：静态方法 `parse(token, Map<String,PublicKey> publicKeys, String hmacSecret, boolean legacyHmacEnabled)`——Base64URL+Jackson 解 header 的 kid/alg（参照网关 `readHeaderValue` 实现）；alg=RS256 按 kid 查公钥 `verifyWith(PublicKey)`；alg=HS* 且 legacy 开启走 HMAC；未知 kid/alg/关闭态抛 `JwtException`（原样抛出，兼容现有异常处理）。
2. **apex-common 新增 `common/security/JwksFetcher`**（A2 共用）：WebClient 拉取 jwks.json → JWK Set 解析（kty=RSA、n/e→RSAPublicKey、kid）→ 缓存 + 按 `apex.jwks.refresh-interval-seconds`（默认 300）刷新 + 失败保留旧快照并告警；绑定 `apex.jwks.*`（对齐 Nacos 预留）。
3. **apex-system**：新增 `CenterJwtKeyProperties`（prefix `apex.system.jwt-center`：`public-keys` Map<kid,base64>、`legacy-hmac-enabled` 默认 true）；`JwtAuthenticationFilter` L244 改经注入的 `JwtMultiKeyVerifier` 解析（公钥 Map 来自配置，可选 JwksFetcher）；认证中心令牌分支 L250 逻辑不动，更新 L102/L247 过时注释；**核实并保证认证中心令牌不触发主应用滑动续期**（`tryRenewToken` 仅对主应用 `type=access` 令牌生效，避免 RS256 令牌被 HS256 链路重签）。
4. **workflow/office-service** 的 `IdentityRelayAuthenticationFilter` 对齐 file-service 多 kid 模式（新增 `workflow.security.jwt-public-keys-base64`、`office.security.jwt-public-keys-base64`，保留旧单键兼容）。
5. **网关**：无代码改动；配置文档说明 Nacos `apex.gateway.jwks.ks` 接入认证中心公钥。
6. **配置**：apex-system、workflow、office 的 application.yml 增加新配置占位；`.env.example` 同步。

### A2 JWKS 闭环
7. **认证中心**：`OAuth2Service.jwt()` 切换为 `JwtKeyMaterialService.sign(subject, claimsMap, ttl)`（iss/aud/client_id/tenant_id/token_use/scope 经 claims 携带，kid 由 sign() 写当前轮换 keyId）；`OAuth2Properties` 静态钥保留一个发布周期作回退（新开关 `auth-center.oauth2.legacy-key-in-jwks` 默认 true 控制聚合输出是否并入配置钥）；`OAuth2MetadataService` 新增聚合 jwks（遍历 `availablePublicKeys()` 投影 kty=RSA/use=sig/alg=RS256/kid/n/e，复用 `unsigned()`），构造器注入 `JwtKeyMaterialService`；`OauthMetadataRouter` jwks handler 改响应式 Mono body；introspect/revoke 不动（DB 哈希查表，与签名无关）。
8. **网关 JWKS 拉取**：`GatewayJwtVerifierService.refreshKeys()` 增加远程拉取合并（`apex.gateway.jwks.remote-url` + `remote-enabled`，默认指向 `/.well-known/jwks.json`；失败保留快照告警；静态 ks 列表兜底，hmac-legacy 保留）。
9. **下游接入**：system + workflow/office/file 密钥来源支持 `apex.jwks.*` 拉取模式（JwksFetcher bean + 各 filter 消费）；静态公钥配置保留为兜底。
10. **文档与批准口径**：`docs/05-operations/configuration.md` 新增"JWKS 闭环"小节 + JWT 段更新；方案文档补记 v3.1 批准口径（D01–D14 采纳推荐）。

### 明确不做（本批）
- 撤销传播/会话/MFA/consent（A3–A5 后续批次）；主应用签发链路切 RS256（过渡期主应用仍 HS256 签发自身令牌，网关双算法兼容）；
- 前端：A1/A2 无前端功能变更，仅回归 401 拦截与滑动续期（写入报告）。
