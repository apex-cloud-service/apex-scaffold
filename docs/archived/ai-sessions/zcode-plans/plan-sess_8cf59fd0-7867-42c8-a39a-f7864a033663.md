## Context
当前项目的六域拆分与中台能力主体已建立，但上一轮评审发现六类闭环缺口：开放调用未到业务 Handler、组合部署装配不完整、事件存在丢失路径、安全治理未全部生效、计量口径不完整、部署与验收交付遗漏。本次修复全部已核验的问题及其直接调用链缺陷，不通过修改完成状态、降低测试门槛或扩大模块数量来掩盖问题。

只读探索进一步确认了事件信封未持久化完整身份、容器构建模块清单过时、网关日志数据库归属不一致等关联问题，需要一起处理。两个探索代理因额度不足中断，其未完成部分在实施前继续逐文件核验；目前没有代码变更。

## 实施原则
- 按下述批次顺序实施，每批先补失败用例，再修复、测试、检查 diff；不并发运行多组构建。
- 保留 system 接口层在业务库、其他域接口层在各 service 的现行归属；boot-all 只编排，不复制业务代码、不全根扫描、不混用六域数据库。
- 复用 `Result`、Reactor Context、`BlockingIoSchedulers`、既有 JWT/JWKS、领域端口、同步事务与 Outbox；不虚构应用用户 ID、不建立第二授权服务器。
- SQL 仅追加所属域下一版本，MySQL/PostgreSQL 配对，历史迁移不改写。新增依赖、分类产物与配置契约同步维护现有 AGENTS/文档。
- 不提交或推送，不覆盖真实密钥、用户环境与数据库；真实运行验证使用隔离资源。不开通生产发布或真实告警通知。

## 批次一：开放调用与统一安全
1. 统一已验签身份解析，明确区分用户、开放应用与内部服务主体。应用保留 `client_id/tenant_id/scope` 协议；普通用户保留原有声明。声明冲突、缺租户、错误 issuer/audience/token-use 均拒绝，不从任意请求头补身份。
2. 修复网关租户中继，并建立四组开放能力的显式承接 Router/适配 Handler：用户组织、文件、工作流、消息。沿用 `/open-api/**` 对外路径，复用应用服务，保留既有管理接口；开放应用只能进入 scope 允许的开放端点，不能借应用令牌调用普通管理端点。
3. 将服务侧订阅判断放到已认证身份之后，依据实际路由能力与已验签主体触发；marker 仅辅助观测，删头不能绕过，伪造头不能改变租户/能力。
4. 给内部接口建立受认证的服务调用边界及调用方/端点权限白名单，并覆盖对应 WebClient 调用。采用独立内部请求认证：每调用方配置凭据，签名绑定方法、目标路径/查询、请求体、时间与 nonce，校验目标服务和允许的租户范围，拒绝重放与篡改；不改变对外 OAuth 协议。登录前租户查询等引导调用无需依赖先取得用户令牌，避免认证循环。缺少生产凭据明确启动失败，不保留匿名内部通道。
5. 接通 integration 权限与审计实际执行者，复用现有授权端口，扩展相关扫描/pointcut；检验管理权限、写操作审计、只读不新增操作日志。用端到端测试证明注解执行而非只测试注解存在。
6. 核对并修复本调用链中的 office 用户查询空实现、开放应用禁用状态等已证实缺陷；未证实的猜测不机械修改。

代表文件：`apex-gateway/.../filter/UserContextRelayFilter.java`、`OpenApiScopeGatewayFilter.java`；`apex-common/.../openapi/OpenApiCapabilityGuardFilter.java`、`.../audit/ReactiveOperationLogAspect.java`；各 service 的身份过滤器、SecurityConfig、Router/Handler；system/auth 开放应用与客户端适配代码。

## 批次二：事务事件与可靠分发
1. 定义版本化事件信封，稳定携带 eventId、tenantId、traceId、发生时间、事件类型及业务负载。当前 `BaseDomainEvent` 元数据被 `@JsonIgnore` 排除，不能只给现有 JSON 加重试；修复持久化/还原与消费链，保留旧消息的明确兼容读取策略。
2. 用现有 `TransactionalOutboxExecutor` 和同步事务模式，把工作流关键状态写入、system 用户/组织/租户变更与 Outbox 追加放进同一数据源、同一同步事务和 JDBC 调度边界；移除 Handler 提交后直发和吞错路径。
3. 补齐真正的事件通道：local 实际交付给订阅者，remote 从已提交 Outbox 发出，auto 按订阅方位置选择。投递结果显式等待本地处理确认或 broker ack；失败保留待重试，达到阈值进入 DLQ，不能提前标记已完成。
4. 消费端以租户＋稳定 eventId 幂等处理，覆盖重启、重复、部分失败；不把缓存失效 TTL 描述为强一致主数据同步。关键投影/撤销建立明确失败重试或回源保障。
5. 检查并追加 workflow 等实际缺少的 Outbox/幂等存储迁移，保持 Seata 与当前 Outbox 的互斥限制。

代表文件：`apex-common/.../event/BaseDomainEvent.java`；`apex-infrastructure-messaging/.../event/DomainEventMqBridge.java` 与 Outbox dispatcher/store；`apex-workflow/.../application/service/WorkflowService.java` 及同步事务端口；workflow-service 的 `LocalWorkflowEventPublisher`、`MqWorkflowEventPublisher`、`WorkflowHandler`；system 用户/租户事务实现和 auth 消费者。

## 批次三：可运行的组件与组合部署
1. 补齐 system 组件入口；修正其他组件对不存在协议包的扫描，避免组件入口与原运行入口重复装配。
2. 各 service 在原模块产出可复用的普通运行适配分类 JAR，保留接口/安全/持久化装配源码归属；boot-all 不依赖嵌套可执行 fat JAR，不引入库反向依赖 service。
3. boot-all 改为单 JVM 内隔离的域上下文协调器，各域独立 Environment、数据源、事务、Mapper、安全链和迁移链。采用明确的域端口，外部仍由现有网关统一入口；不宣称单上下文或自动单端口。
4. 分类产物提供域限定配置、Mapper 与迁移资源路径，历史 SQL 内容不变；每上下文只启用所属域自动配置，避免共享 classpath 的同名 `application.yml`、Flyway 路径与 Bean 冲突。
5. 明确 subset 必需能力闭包：依赖域可由同 JVM 组件或已配置远端服务提供；缺失则启动失败。所有本地目标均正确路由，跨域数据所有权不变。
6. 替换“类名集合即装配成功”的测试，真实启动全量和合法子集，执行登录与至少一项跨域业务，检验非法拓扑、停机、独立迁移以及组件禁用行为。

代表文件：`apex-boot-all/pom.xml`、`BootAllApplication.java`、现有装配/拓扑测试；六域组件自动配置；各 service POM 与装配入口。依赖表和单进程多上下文运行说明同步更新现有文档。

## 批次四：能力计量口径与租户权限
1. 将目录能力合法性与“有无调用 URI 映射”分离，修复 `iot-device` 默认不可查询；单租户无调用时生成零调用行，仍返回文件/设备/消息存量。
2. 调用次数定义为通过网关安全断言并进入下游调用的请求数，包含下游成功与失败，区分调用次数与成功次数；不再把仅有操作注解的日志当全量计量。
3. 复用网关现有已验签身份、routeId 和访问记录，新增稳定 capability/client/tenant/requestId 计量维度。计量持久化与审计采样解耦，以稳定 ID 去重、持久化重试，不把写入失败静默当完整统计。
4. 网关数据保持网关数据库归属，补齐独立迁移和数据源装配；system 经受认证内部统计契约聚合，不跨库 SQL 查询。历史 system 中的网关迁移保持不变。
5. 统一时间范围、零值、数据源失败/不完整标识与分页兼容；用量与内部 stats 端点校验受信租户范围，跨租户仅允许明确平台权限/服务权限入口。

代表文件：`CapabilityUsageProperties.java`、`CapabilityUsageService.java`、`CapabilityMetricClient.java`、`CapabilityUsageQueryRepositoryImpl.java`；网关访问日志/计量存储；file/office/integration 内部统计及契约测试。
