## Context

目标是评审当前全部 Maven 模块，使用合适的 Java 设计模式、SPI 与 lambda 降低重复、提升可维护性，并同步受影响的文档、配置、脚本和测试，重新生成可追溯的测试报告。

目前完成的是**全仓候选搜索与关键源码复核，不是全部代码审计完成**。当前约 45 个 reactor 项目，最终范围按根 POM 递归解析，不固定数量。同日 BE-044 已实施部分设计模式/SPI 加固，本轮以当前源码为准做增量复审，避免重复改造。

已核实的重点：
- storage 已有策略接口、注册表和 `StorageProviderLoader`；integration 已有 `ConnectorLoader`。Seata 已有模式枚举和条件装配，不重新搭建 SPI 框架。
- `SsoProtocolAdapterFactory` 两处枚举协议并缓存已有 Bean，适合合并分派；其接口和四参数构造器需要保持兼容。
- `MeilisearchAdapter` 在单条、全量与增量索引中重复维护资源类型分派，适合收敛资源策略。
- 部分内部 Handler 的错误映射确实重复，但 auth、common 的 HTTP 状态与错误语义不同，不能直接统一。
- 各服务认证过滤器存在重复验签内核，但开放应用、HMAC 开关、文件访问上下文、office WebSocket 票据等行为不同，不能整体合并。
- `scripts/test/generate-test-report.sh` 仍使用旧单层路径、硬编码模块清单且仅统计 Surefire，与现有目录和文档声明不符，必须修复。

## 2. 全模块评审与问题收口

沿根 `pom.xml` 的 `<modules>` 建立覆盖清单，依次评审 shared、components/business、starters、services、applications、tools。每个模块核对生产类及其调用链、对应测试、POM、自动装配资源与配置。

评审包括：
- DDD 依赖方向、组件/运行模块职责、循环依赖与重复框架代码。
- 策略、工厂、模板方法、责任链、观察者与适配器是否恰当；新增抽象必须有真实扩展点或重复逻辑作为依据。
- Java SPI 与 Spring 集合注入/自动装配的职责区分、第三方 provider 的发现及生命周期。
- lambda、方法引用、普通集合处理的可读性；不批量将循环替换为 Stream，不引入 `parallelStream`。
- 阻塞 I/O 隔离、事务/Outbox 同线程边界、Reactor Context、错误传播、取消与顺序语义。
- 租户、安全、权限注解实际生效、日志脱敏、错误响应与配置默认值。

每条发现记录精确位置、证据、严重度、推荐修复与测试；明确区分已深读、仅静态扫描、确认无须改动。发现有证据的缺陷时补失败测试后修复；涉及对外契约、模块坐标、迁移或部署拓扑的变化，先按治理规范出规格并单独确认，不混入兼容性重构。

## 3. 分批兼容性优化

### A. 策略分派与职责收敛

**SSO 工厂**
- 修改 `apex-components-parent/apex-system/src/main/java/com/apex/scaffold/application/support/sso/SsoProtocolAdapterFactory.java`。
- 保留 `SsoProtocolAdapter` 接口及现有 public 四参数构造器；构造时建立不可变协议注册表，`getAdapter()` 与 `isSupported()` 共用查表，移除无实际创建作用的缓存。
- 使用 `Locale.ROOT` 规范化协议名称，保留空值、空白、未知协议的异常类型与消息。
- 参考同模块 `application/service/login/LoginStrategyProvider.java` 的策略管理思路，但不复制其默认策略或重复覆盖行为，也不宣称简单 Map 已实现自动 SPI 扩展。
- 新增真实工厂测试：四个协议、空白/大小写、未知输入、非英语默认 Locale、返回同一已装配实例。

**搜索资源分派**
- 修改 `apex-components-parent/apex-system/src/main/java/com/apex/scaffold/infrastructure/search/MeilisearchAdapter.java`，将六种资源的文档读取、全量 ID 与增量 ID 查询收敛到模块内策略注册，使用方法引用/lambda 接入已有具体查询方法。
- 单条、批量、重建和增量流程共享同一资源注册来源；不新建六套框架或改变索引文档结构。
- 保留未知资源、过滤条件、时间格式、租户上下文、批次顺序与 JDBC/remote/general 调度边界。
- 扩展现有 `apex-system/src/test/java/com/apex/scaffold/arch/BlockingIoIsolationTest.java` 并补资源分派行为测试。

### B. SPI 与自动装配验证

复用现有：
- `apex-starters-parent/apex-storage-spring-boot-starter/.../storage/StorageProviderLoader.java`、`StorageRegistry`、`StorageAutoConfiguration`。
- `apex-components-parent/apex-integration/.../connector/domain/ConnectorLoader.java`。
- messaging 的 `MqLocalTransactionAutoConfiguration`、`NotificationConsumerAutoConfiguration`。

重点补真实描述符/隔离类加载器的发现测试及装配顺序测试，而非仅模拟迭代器：好/坏 provider、可选 SDK 缺失、空类型、重复类型、内置优先、默认类型不可用、自定义 Bean 让位、开关关闭零装配。保持 storage 与 connector 各自既有重复处理政策，不统一成一个通用 loader。只修测试证明的缺陷，不为了减少分支改动 Seata 装配时序。

### C. 跨服务重复与复杂方法

- 对已确认同型的 `FileInternalHandler`、`OfficeInternalHandler` 错误响应先建立契约测试，再将真正等价的部分收敛为命名明确的内部端点响应策略；保留 HTTP 状态、业务码、消息、traceId、日志与 Content-Type 行为。复用前核对 `Result` 工厂；不能直接改用行为不同的 `HttpStatusUtil`。
- 认证过滤器只在完整差异矩阵与正反向测试建立后抽取无域依赖的验签内核；各域 WebFilter、身份对象、HMAC 准入、开放应用和 WebSocket 票据仍留原模块。出现无法证明兼容的差异时保留实现，不强行合并。
- 其余模块根据评审证据进行小批职责拆分和 lambda/方法引用优化；不按文件长度机械拆类。
- 已有 `SensitiveDataUtil → DataMaskUtil`、`LoggingFilter → LogSafetyUtil` 委托保留。搜索手机号脱敏与公共工具边界不同，不能作为纯重构直接替换；若确认泄露问题，作为独立安全缺陷处理并补测试。

mvnd -T4 -B -pl :<受影响模块列表> -am spotless:check
