## Context
目标是让项目文档的内部导航正常使用，而不只是让现有检查器显示通过。已确认至少 89 处失效引用，包含退役模块路径、目录迁移后的相对路径，以及 HTML 文档搜索和 Mermaid 查看器的导航数据。现有 Markdown 检查器存在反引号解析和 HTML 链接遗漏。

## 实施方案
1. **补齐可靠校验**：在 `apex-tools-deployment` 中复用已依赖的 CommonMark/GFM 解析器，以 AST 提取 Markdown 链接、图片及标题，复用 `GitHubHeadingSlug` 和渲染器的可见标题文本/重复标题规则。补查 HTML href/src 与显式锚点，保留有效目录链接，避免把代码示例当成链接。为已确认的漏检形态增加回归测试，不新增依赖。
   - 关键文件：`DocLinksChecker.java`、`DocLinksCheckerTest.java`；按需复用 `MarkdownPageRenderer.java` 的标题逻辑。
2. **修复全部实际断链**：运行修正后的检查器扫描全仓 Markdown，逐项核对真实目标；修复 `docs/03-api/api-routes.md` 的 Router/Handler 链接并收窄相关过时表述，以及 `docs/04-development/mermaid-viewer-guide.md` 的查看器链接。
3. **修复 HTML 文档导航**：核对文档目录下 HTML 的本地 href/src、查看器 fetch/选项值及搜索页文档列表，修复迁移路径。没有实际文档的搜索条目移除，不创建占位文档；第三方图标 README 的空文档链接改为对应现有图标。
   - 代表文件：`docs/04-development/doc-search.html`、`mermaid-viewer.html`、`link-test.html`、`test-mermaid-viewer.html`，以及已发现的归档培训 HTML。
4. **控制范围**：保留已有目录链接、外部 URL 和有效历史归档；不改业务服务、不添加报告、不提交或推送。
