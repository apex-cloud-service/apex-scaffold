## Apex Scaffold 微服务架构改造方案

### 核心策略
将当前单体应用按限界上下文拆分为 5 个独立微服务 + 1 个 API 网关 + 1 个共享 SDK，渐进式迁移，保持前端 API 契约不变。

### 拆分边界
1. **apex-common-sdk** — 共享基础库（从 apex-common 剥离）
2. **apex-gateway** — API 网关（新建，Spring Cloud Gateway）
3. **apex-auth-service** — 认证授权中心（从 apex-auth-center 升级，已独立）
4. **apex-system-service** — 系统管理服务（核心业务）
5. **apex-workflow-service** — 工作流服务（从 apex-workflow 独立，已切片）
6. **apex-office-service** — 办公集成服务（office 子域剥离）
7. **apex-file-service** — 文件存储服务（File/Storage 剥离）

### 关键设计
- **服务间通信**：OpenFeign（同步） + RocketMQ + Outbox（异步事件）
- **数据一致性**：本地事务 + Saga 编排 + 幂等消费
- **数据库拆分**：每个微服务独立数据库（apex_auth/apex_system/apex_workflow/apex_office/apex_file）
- **认证改造**：网关层轻量 JWT 校验 + 微服务层完整验证
- **可观测性**：Prometheus + Grafana + Zipkin + Loki + Sentinel

### 实施路线图（约 15 周，7 个 Phase）
- Phase 1：基础设施准备（2 周）— SDK 拆分 + Gateway 搭建 + Feign 框架
- Phase 2：认证中心独立部署（1 周）
- Phase 3：工作流服务独立（2 周）
- Phase 4：办公集成服务独立（3 周）
- Phase 5：文件服务独立（2 周）
- Phase 6：系统管理服务重构（3 周）
- Phase 7：全面联调与压测（2 周）
