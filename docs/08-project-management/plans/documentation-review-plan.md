# Apex Scaffold 项目文档与配置全面评审与重构计划

## 一、项目概览

**项目名称**: Apex Scaffold  
**版本**: 1.2.0  
**技术栈**: Java 17 / Spring Boot 3.5.15 / WebFlux / DDD 四层架构  
**评审日期**: 2026-09-09

## 二、评审目标

本次评审与重构任务包含三个核心目标：

### 目标 1：文档、脚本、配置与实现的一致性评审
- 评审所有文档（docs/）是否与项目实际实现保持一致
- 评审所有脚本（scripts/）是否反映当前系统状态
- 评审配置文件（application*.yml）是否准确描述系统行为
- 评审 SVG 架构图表是否与当前架构匹配
- 识别并修复所有不一致之处

### 目标 2：环境变量统一管理
- 将各环境配置文件中的配置项迁移为环境变量驱动
- 创建统一的环境变量配置文件（.env）
- 确保所有敏感配置通过环境变量注入
- 优化配置文件结构，减少硬编码

### 目标 3：SQL 脚本 Flyway 迁移
- 将项目根目录的 SQL 脚本迁移到 Flyway 版本化迁移
- 确保数据库变更可追溯、可重放
- 清理临时 SQL 脚本文件

## 六、实施原则

### 6.1 安全原则
- **禁止硬编码敏感信息**: 所有密码、密钥、Token 必须通过环境变量注入
- **向后兼容**: 环境变量提供合理默认值，确保现有部署不受影响
- **审计追踪**: 所有配置变更记录在案

### 6.2 工程原则
- **只追加不修改**: Flyway 迁移脚本一旦执行不可修改
- **最小影响**: 配置文件修改保持最小化，只改必须改的
