# 测试完整性补充与全量测试报告实施计划

## 仓库调研结论
- 项目为 Maven 多模块工程，包含 common、domain、application、infrastructure、interfaces、example、generator、license 等模块。
- 已存在大量单元测试、集成测试和契约测试，但测试文件数量较多，当前需要通过主代码与测试代码的映射、覆盖率结果及失败测试结果识别真正缺口，避免仅按文件名机械补测。
- 根项目约定使用 `mvnd test` 执行单元测试，`mvnd verify` 执行包含 Failsafe 的集成测试，`mvnd clean test jacoco:report` 生成 JaCoCo 报告；HTML 覆盖率通常位于各模块 `target/site/jacoco/index.html`。
- Surefire 默认排除 `*IntegrationTest`、`*E2ETest`、`*LiveTest`、`*SmokeTest` 等测试，Failsafe 负责主要集成测试；因此全量验证需要同时覆盖单元测试与集成测试阶段。
- 项目已有 `docs/reports/` 和 `.trae/documents/` 两类报告目录。此次测试报告拟保存到 `docs/reports/`，并引用各模块生成的 Surefire/Failsafe/JaCoCo 证据路径；如需新增汇总文档，仅在测试执行完成后生成。

## 文件和模块
- 各 Maven 模块的 `src/main/java` 与 `src/test/java`：建立测试覆盖映射，定位无测试或分支明显未覆盖的公开业务逻辑。
- 现有测试类：先运行并按失败、编译错误、Mockito 严格桩、环境依赖和覆盖率门槛分类修复。
- 需要补充测试的业务类对应 `src/test/java` 文件：沿用项目现有 JUnit 5、Mockito、Reactor Test、Spring Test 和 ArchUnit 等依赖与风格，不引入未经确认的新库。
- `docs/reports/`：测试执行完成后写入带日期和范围的综合测试报告。

## 实施步骤
1. 进一步盘点所有模块的主代码、测试代码、测试资源和 Maven Profile，生成待核查的测试缺口清单。
2. 执行单元测试与测试编译，收集 Surefire 输出、编译错误、失败测试和 JaCoCo 覆盖率，区分缺失测试与既有测试/环境问题。
3. 按风险和业务边界补充缺失测试，优先覆盖认证授权、租户隔离、工作流、路由/OpenAPI、数据访问边界、异常处理、并发和配置校验等核心路径；同时修复因测试 API 漂移导致的测试编译问题。
4. 逐模块执行单元测试，修复失败项并重新生成 JaCoCo 报告；再执行全量 `verify`，验证集成测试和 Failsafe 阶段。
5. 执行项目要求的 lint、格式化检查和类型/编译检查（以仓库实际可用命令为准），确认测试变更没有引入质量问题。
6. 汇总测试数量、通过/失败/跳过、覆盖率、失败原因、环境依赖、执行命令及证据路径，生成并保存综合测试报告。

## 依赖与注意事项
- 全量集成测试可能依赖数据库、Redis、消息中间件或外部认证服务；不可用时应在报告中明确区分环境阻塞和代码失败，不得伪造通过结果。
- 遵循仓库硬约束：不引入敏感信息，不记录密钥；代码中不添加注释；测试需验证租户作用域、认证上下文和幂等隔离等安全约束。
- 任何新增测试应优先验证可观察行为，不为单纯提高数字而修改生产代码或排除测试。
- 报告文件只在测试结果真实产生后创建，避免提前生成空报告。

## 验证
- `mvnd test`：单元测试执行成功，或报告明确列出失败项及原因。
- `mvnd verify`：集成测试/Failsafe 执行成功，或记录外部依赖导致的阻塞。
- `mvnd clean test jacoco:report` 或等价覆盖率命令：生成各模块 JaCoCo HTML/XML 报告并核对门槛。
- `mvnd spotless:check`、项目可用的 PMD/编译检查：确保代码质量检查通过。
- 检查综合报告与 `target/surefire-reports`、`target/failsafe-reports`、`target/site/jacoco` 证据相互一致。

## 风险及处理
- **测试范围过大导致无法一次完成**：先以全模块扫描和实际执行结果确定缺口，按核心模块分批补充，保持每批可验证。
- **测试编译或依赖环境失败**：记录最小复现命令和完整失败原因，优先修复代码/API 不匹配；外部服务问题单独标注。
- **覆盖率门槛失败**：补充真实行为和边界测试，避免降低门槛或跳过测试。
- **并行执行造成共享资源冲突**：集成测试按 Maven 配置顺序执行，必要时隔离数据库/端口/临时目录，并在报告中记录环境配置。
