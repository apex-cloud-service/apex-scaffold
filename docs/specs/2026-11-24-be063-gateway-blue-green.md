# BE-063 Wave D2：网关蓝绿切换规格（独立复核通过）

## 范围

只覆盖同一隔离 Kubernetes namespace 内的网关入口，业务服务、数据源和身份系统保持现有契约。D1 的独立稳定/金丝雀入口保留原用途；不以金丝雀权重 100% 代替蓝绿，也不把网关双版本称为全栈双环境。首次实施限新建隔离环境，不尝试修改既有 Deployment 的不可变 selector。

## 拓扑与切流

| 资源 | 职责 |
| --- | --- |
| 蓝、绿 Deployment | 各自使用完全互斥且不可变的颜色 selector，分别固定镜像摘要、就绪探针及独立 PDB；活跃和预览身份不随颜色名称固定。 |
| 蓝、绿 Service | selector 永不随切流改变，各自只接对应颜色的 Ready Pod；按下文校验 EndpointSlice、转发地址和实际运行镜像。 |
| 主 Ingress | 固定 host/path/TLS，仅将目标 Service 名从当前颜色切换为另一颜色，不修改两个 Service selector，也不新建覆盖主路由的 Ingress。 |
| 专属控制器与入口地址 | 入口地址只分发到本控制器实例；控制器仅监听专属 namespace 与专属 IngressClass，不接收无 class 资源，不与 D1 或其他入口共享监听面。 |
| 预览接入 | 通过受控的集群内调用直达被动色 Service；不为预览打开匿名公网路由，不绕过业务身份校验。 |

1. **预检**：显式指定测试 context/namespace，核对对象 UID、Ingress class/controller、主入口当前目标与批准的镜像摘要。按下文确认入口独占防护已生效，并枚举该控制器实际加载的入口规则，确认无重复、通配、重叠路由或金丝雀导流；无法枚举完整作用域即停止。拒绝目标不符、端点混色、证据缺失或任一颜色不能独立承载约定峰值的环境。
2. **准备**：部署被动色，核对 rollout、两个 Service 全部 EndpointSlice、探针、鉴权及代表链路。同一窗口保留原颜色和容量；若启用 HPA，应分色管理并确认被动色切换前副本足够，不依赖切流后的临时扩容。
3. **切换**：只有受控发布写入者可改主 Ingress。两色端点须在切换前重新读取和校验，再原子比较 UID、resourceVersion、当前后端及写入栅栏，且只更新目标 Service。拒绝过期输入与目标未知；已处于目标时仅恢复验收，不再次写入。切流请求超时后先读回实际对象，未知时冻结，不盲目重试。
4. **验收**：覆盖各承流 Ingress 实例，分别确认新请求收敛和旧色在途请求/长连接排空，再结束观测。控制面成功、一次外部探测或单个控制器成功均不代表数据面收敛。SSE/WebSocket 按现有重连与补偿语义验收，不声称已有连接迁移。
5. **切回**：若已确认 Ingress 指向新色，但部分控制器未收敛或业务门槛失败，不要求先完成正向收敛；重新验证旧色容量、健康和兼容性、双侧身份及写入栅栏，以最新 resourceVersion 反向更新，按同等条件验证数据面。入口状态无法确定、旧色不健康或证据缺失则冻结发布，不自动更新。观测及排空均通过前不缩容、不删除原版本、不执行破坏性数据变更。

## 写入、验证与排空约束

- **单写与栅栏**：蓝绿主 Ingress 使用独立对象名和专属写入身份；D1 apply/灰度、人工常规账号、GitOps 均无该对象写权限，GitOps 不同步其后端字段。租约用作调度，不能单独充当写入栅栏：接管时先原子推进 Ingress 上的单调栅栏，并使旧写入权限失效；切流请求必须同时比较栅栏、UID、resourceVersion 与当前目标。发布入口校验当前执行身份与栅栏绑定，禁止以刷新旧执行者的栅栏继续写入。若权限或接管控制无法落实，则仅保留人工冻结的演练规格，不开放自动切流。
- **持续入口独占**：在新建的专属拓扑中，先安装并验证拒绝式准入，再创建主 Ingress 和对外暴露控制器。准入按固定 namespace 匹配所有 Ingress 写入，不以请求方可变的标签或 class 筛选。拒绝所有其他 Ingress 的创建与更新；主 Ingress 固定 class、host、path、TLS 和非导流配置，正常发布只可更新许可的蓝/绿后端与栅栏，拒绝删除、替换及新增导流注解。准入故障必须拒绝写入，同时禁止发布身份修改准入、控制器监听范围、额外路由来源或入口地址绑定；这些设施不得在发布窗口变更。预检、切换、观测、回切和排空期间持续有效，不用重复扫描替代准入。若无法证明入口地址独占或防护持续有效，冻结写入和清理，按人工恢复预案处理，不自动切回。
- **端点身份与容量**：校验 EndpointSlice 的 namespace、Service UID 所有权与 service-name 标签、端口名/协议/端口及端点地址与 Pod IP 和 Service 目标端口一致；校验 Pod → ReplicaSet → Deployment 的 UID 链、颜色、发布版本与实际容器镜像摘要（多架构镜像明确记录允许的平台摘要映射）。只按唯一 Ready、非终止的 Pod UID 计数；双栈或跨 Slice 重复不能增加容量。切换或回切前均重新采集双侧证据，不能用 D1 的至少一个 Ready 端点代替容量门槛。
- **数据面与排空**：枚举所有承流控制器；用受控逐实例探测加真实入口探测，依据受信控制器上游日志或内部响应标识关联请求 ID、Pod UID 和版本，保留新连接与复用连接的分项证据。旧色用网关/控制器按版本分组的在途 HTTP 与 SSE/WebSocket 活动量验证排空，预先约定截止时间。指标不可得、任一实例无法探测或到期仍有活动时保留旧色，不自动缩容。若演练允许主动断连，须单独验证客户端重连与补偿，再决定清理。

## 验收与证据

- 本地契约用例覆盖错误 context/namespace、跨 namespace 入口冲突、空端点、地址/端口不符、UID 重复及归属交叉、过期租约写入、其他发布入口并发覆盖、写入生效但客户端超时、部分控制器收敛后回切、已切换后重跑、回切前旧色容量不足和排空超期。预检失败、API 冲突和等待超时都不得触发自动清理。
- 隔离集群注入预检后并发创建重叠 host/path、通配和导流规则的请求：专属 namespace API 必须拒绝，其他 namespace 不得被该入口加载；覆盖切换前、观测中与回切中。另验证现有对象更新或删除主入口、修改控制器监听或绕过准入均被阻止；准入故障时合法切流也应失败。以控制器逐实例路由/流量和审计结果确认，无竞争路由进入数据面。
- 在专用集群记录 Kubernetes、Ingress Controller、镜像摘要、CPU/内存、Ready 数和测试数据；持续覆盖预览、蓝转绿、绿转蓝及中断恢复。每段以独立连接样本按 Pod 汇总请求量，并分开验证连接复用和长连接排空。不以均匀分布作为无条件假设；至少验证无跨色端点、目标颜色多副本有流量、单副本失效后仍满足预先确认的 SLA。
- 与 Wave C 的容量基线一起确认并发、持续时间、允许的错误率/p95/p99、最低 Ready 数和最大收敛时间，先确定门槛再跑。限流、熔断及重试应分别标记，不能用峰值吞吐或健康端点代替业务验收。未提供隔离环境和批准阈值时，保持未验证，不调生产参数。
- 本地 `kind get clusters` 未发现已有 Kind 集群。本篇仅是规格，未创建集群、未切换任何入口；独立 R5 后另开实现租约。实现未通过真实切回演练前不得上线。
