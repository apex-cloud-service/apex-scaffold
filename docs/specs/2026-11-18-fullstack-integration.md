# 2026-11-18 前后端全量联调与 Podman 基线方案（FE-029 / BE-043）

## 背景

前端 `apex-admin-web` 与本仓库已有真实联调记录：FE-026/BE-036 通过网关验证 18 条接口，并修复了办公列表、权限快照、菜单范围和租户传播等问题。这些证据不覆盖全部前端 API、页面写操作、分页与错误语义，也不证明当前 Podman Compose 网络中的前端反代已端到端可用。前端部署文档仍以 Docker Compose 为主，需统一到后端现有 Podman Compose 栈。

## 目标

- 使用 Podman / `podman-compose` 建立可重复的开发联调环境：本仓库 `podman-compose.yml` 是唯一全栈编排入口；前端镜像独立预构建，再由后端 Compose 的 `apex-admin-web` 服务加入同一 Podman 网络。
- 按前端全部 `src/api/` 导出函数，对照本仓库执行 Router/Handler、DTO、权限、租户、分页与响应包装，形成逐接口差异矩阵。
- 经真实容器链路验证登录/刷新、身份/菜单、首页聚合、主要业务域列表、具备安全测试数据的写操作闭环及可用的 SSE/WebSocket 能力。
- 只修复由执行证据确认的后端缺陷，补充后端定向测试；同步前端适配、文档、Compose 配置/脚本、测试代码和测试报告。
- 对无第三方凭据、真实测试数据或环境条件的能力明确列为未验证，不以 mock 或历史结果代替本轮真实证据。

## 影响面

- 后端源码与测试：仅定位到缺陷的最小服务模块文件；可能涉及 system、auth、office、workflow、file、integration、knowledge、aggregation 等运行边界。
- 后端配置：`podman-compose.yml` 仅在真实环境验证确认存在缺陷时调整；检查并修正前端服务的 profile/健康依赖，不扩大生产默认暴露面。
- 后端文档：`docs/03-api/`、`docs/06-testing/`、`docs/specs/`、`docs/records/`、`docs/README.md`、本任务卡及变更记忆台账。
- 前端写入归 FE-029：`src/api/**`、相应页面与测试、Podman Compose/镜像脚本和联调文档/报告。
- FE-029 与 BE-043 由同一 R0 串行协调；共享契约和数据库迁移禁止并行改写。实际运行验证覆盖方案列出的关键链路，不声称所有映射接口都已逐条完成真实 E2E。

## 兼容性

- 不升级技术栈，不为单侧实现改变现有 API 语义；必须改契约时 FE/BE 同步修改、补兼容性说明与回归测试。
- 后端 `.env` 从 `.env.example` 创建并按配置指南填写本地必填安全密钥；项目名固定为 `apex-scaffold`，预期网络名为 `apex-scaffold_apex-network`。前端由后端 Compose 唯一服务启动并加入该网络，反代目标为 `http://apex-gateway:8080`，不使用已退役单体服务名。
- 所有容器启停、构建和联调命令均使用 `podman` / `podman-compose`；不使用 Docker Compose 作为实际运行路径。
- 不提交密钥、令牌、生产数据或本地环境文件；测试记录和数据必须限定在本地环境并可清理。

## 回滚方案

- Compose、脚本、文档和代码修复分批变更，可按文件或提交回滚；已提交变更使用 `git revert`，禁止硬重置覆盖工作区。
- 不删除现有 Podman 容器、网络、卷或用户数据。执行前记录环境状态；测试后仅清理能确认由本任务创建的测试数据。
- 如需数据库迁移、POM/模块边界或共享 DTO 大范围调整，暂停本方案执行，先单独评审兼容及回滚策略。

## 验收标准

1. R3 独立评审方案通过后再进入执行；前后端任务卡具备 R0、基线、互斥写入范围、具体独立复核者及验收命令。
2. 后端 `.env` 从 `.env.example` 准备且必填本地密钥非空；显式指定 `-p apex-scaffold`；`podman-compose -p apex-scaffold -f podman-compose.yml config` 通过。所需后端服务和前端容器健康；前端容器能解析 `apex-gateway` 并经 Nginx 成功反代。
3. API 差异矩阵静态映射覆盖全部前端 API 导出函数，记录路由、请求/响应/分页/鉴权差异及验证状态；静态映射不等同于全部接口真实 E2E。
4. 真实链路覆盖登录/刷新、身份/菜单、首页聚合、已接入业务域主要列表和安全可回滚的写路径；SSE/WS 实测或列明未验证原因。
5. 后端受影响模块的固定 JDK/mvnd 测试与 `spotless:check` 通过，治理检查通过；前端构建、类型、单元、E2E 和治理检查由 FE-029 记录。
6. 每条真实请求记录方法、路径、HTTP 状态和脱敏响应摘要；两仓同步契约、Podman 配置/脚本、测试代码、分层测试报告和变更记录。
7. 指定的 R5 `integration_final_reviewer` 以独立于执行者的上下文复核最终待复核版本；未验证边界、环境基线、测试数据清理与回滚方式完整留痕后方可关闭。
