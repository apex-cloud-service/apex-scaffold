# BE-065 PMD 全仓规则违规修复

## 背景

BE-064 将 Maven PMD 插件使用的 ASM 升至 9.6 后，Java 21 major 65 解析异常消失。2026-11-23 根目录 `pmd:pmd` 刷新 37 份报告，初次显示 23 个模块、339 条违规；common/auth-service/domain 后续处理后当前 XML 快照为 21 个模块、327 条，均无 `<error>` 节点。P3C 仍输出 XPath `maximum Iterations exceeded` 诊断，因此这些计数不是全量无诊断基线，也不是干净提交 SHA 的基线。

## 目标

逐项修复真实规则问题，保持 PMD 6.55、P3C 2.1.1、所有规则和失败门禁启用，不扩大历史排除清单。

## 影响面（模块+接口+数据）

预计影响多个 Java 源码模块及必要测试。先按模块逐批实施；不改 HTTP/API 契约、数据库迁移、模块坐标或生产部署拓扑。

## 兼容性

每项变更须保持现行业务语义，仅对明显安全的 Javadoc、命名和等价控制流拆分直接处理；涉及常量语义、复杂条件、并发或线程策略的变更须先确认语义并增加测试。

租户状态快照的 `exists`、`expired` 使用 `Boolean`，同仓 Java 消费者随生成的 `getExists()`、`getExpired()` 一起重编译；不保证旧二进制访问器兼容，构件及消费者不能混用。跨进程 JSON 路径、字段名、布尔值及缺省/显式 `null` 按 `false` 解释的既有行为保持不变，提供方未知租户仍返回 `exists=false` 和 `expired=false`。定向验证包含缺省、`null` 和真实布尔取值。

Java 构件存在不兼容变更：租户快照的 setter、全参构造、builder 签名随字段类型变化，不能跨版本反序列化旧 Java 对象。OAuth 的 `OAuth2AuthorizationPort`、`OAuth2ConsentPort`、同意仓储及授权处理器改为 `Oauth…` 命名；四个端口嵌套 record 的所属类型和 `OAuth2Service` 构造签名也随之变化。直接使用这些类型、构造器或自定义端口的 Java 调用方须迁移并重编译；同一 JVM 不得混用新旧构件。HTTP 独立进程的契约核验不代表 Java ABI 兼容。

发布门槛：若选择发布不兼容版本，必须先分配可区分的构件版本，不覆盖已分发的 `1.3.1`；受影响构件及消费方按同一版本重新构建、成套发布和回滚。若必须保留旧 Java ABI，则需另行提供兼容入口及旧调用方回归，不能仅凭本仓重新编译宣称兼容。此次不修改构件坐标，不执行发布。

## 回滚方案

按模块和批次回滚 BE-065 新增的源码/测试差异，不执行全仓 `git restore`、`reset` 或清理；保留原始 PMD XML 快照作为问题发现证据。

## 验收标准

每批定向 `verify` 与 Spotless 通过；全仓 PMD 报告无未处理规则违规，完整 `mvnd -T4 -B verify` 通过；测试报告与对应工作树版本及命令绑定。不得将 PMD 分析错误当作零违规。
