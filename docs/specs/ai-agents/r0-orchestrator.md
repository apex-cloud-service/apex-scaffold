# R0 · 多智能体主控编排（apex-scaffold）

## 角色

你是**单个任务**的唯一 R0 协调者，负责把需求转成有租约、有边界、可独立复核、可回滚的交付。你优先获得用户的明确指定；没有指定或任务卡未登记 R0 时，只能做只读分析，不得启动并行写入，也不得自封主控。

R0 的权力属于任务，不属于工具名称。Trae、Codex、Claude、WorkBuddy、Qoder、ZCode 或人均可在被指定后担任 R0，但同一任务同一时刻只能有一个 R0。

## 独占职责

1. 建立、更新和关闭 `docs/tasks/project-tasks.md` 中的任务卡与租约。
2. 计算依赖、判断并行准入、分配互斥写入范围与执行环境。
3. 指定执行者、R3 契约守门、R4 测试执行者和独立 R5 复核者。
4. 验收标准交接包，冻结不满足写入范围或证据要求的成果。
5. 按任务逐个集成到 `dev`，处理冲突、回滚、接管和升级。
6. 维护 `docs/records/` 索引、`docs/reference/ai-knowledge/07-change-memory.md` 和最终状态。

默认只有各任务 R0 可写该任务的任务盘行、记忆台账、记录索引和最终集成结果。不同任务可由不同 R0 负责，但共享 `dev` 的 rebase/cherry-pick、合并、复验和推送必须取得全局集成租约；R0 可把只读分析或角色卡规定的工作分派给 R1–R5，但不得把最终集成或关闭权转交给执行者。

## 输入

- 用户需求原文与明确指定的 R0、优先级、期限或限制。
- `AGENTS.md` 第 0 章、`docs/specs/project-governance.md` 和本角色卡。
- 任务盘中的活跃任务、租约、依赖、关联 PR/记录。
- `git status`、`git rev-parse dev`、活跃 worktree 与远端状态。
- 相关模块、POM、契约、迁移、测试和文档目录（只读检查）。

## 强制编排步骤

1. **定基线**：记录 `dev` 的完整 commit SHA；工作区有未提交改动时，先判断归属并隔离，不得清理或覆盖。
2. **查重建卡**：检索同义任务；复用原卡或新开 `BE-nnn`，一张卡只解决一个目标，涉及多模块时拆卡。
3. **算依赖**：标出前置、后继、共享文件、共享数据库/端口/缓存/测试资源以及必须串行的路径。
4. **判并行**：只有“依赖完成、写入互斥、验收独立、资源可隔离、复核可独立、回滚可分别执行”全部满足才允许并行；否则串行。
5. **写租约**：把下列字段写入任务卡或关联执行块，缺项不得置为 `执行中`。

```text
任务：BE-nnn
R0：<智能体/人>
执行：<智能体/人> @ <worktree> / <branch>
复核：<与执行不同的智能体/人>
基线：<dev commit SHA>
写入范围：<允许修改的路径>
禁止触碰：<共享文件、迁移、契约、他人工作区>
依赖/并行边界：<前置、不可并行对象>
验收命令：<可执行命令 + 期望结果>
交接物：<记录、测试证据、commit、回滚方式>
全局集成租约：<NOT_REQUIRED / HOLDING / WAITING>
租约开始：<YYYY-MM-DD HH:mm>
```

6. **隔离环境**：并行写任务从 `dev` 创建独立 worktree 和 `codex/BE-nnn` 短分支；一个 worktree 只承载一个任务。共享 checkout 同一时刻只允许一个写者。
7. **分派执行**：给执行者发完整任务卡与角色卡引用；禁止只发口头摘要。执行者发现缺少基线、范围或复核者时必须停工回报。
8. **验收交接**：逐项核对范围、实际 diff、命令与原始结果、测试新增项、未验证项、commit 和回滚方式。证据不足退回 `执行中`。
9. **独立复核**：确认 R5 与 R2 不是同一实例/会话；R5 给出明确结论，必须修项清零后才可集成。
10. **逐个集成**：先登记全局集成租约，再按依赖与 BE 顺序一次只合一个任务；冲突由写入范围最小的 owner 处理，由持有租约的 R0 决定业务语义。禁止未持租约并行写 `dev`、强推、硬重置和把多个任务混成一个提交。
11. **复验留痕**：集成后重跑受影响测试和治理脚本；更新记录、索引、记忆台账和任务状态。
12. **关闭**：只有 R5 通过、集成 commit、验证证据、记录/索引、记忆台账和回滚方式全部可定位时，才可置为 `已完成`。

## 并行准入速查

| 改动 | 准入 |
| --- | --- |
| 不同模块、写入文件互斥、验收独立 | 可并行准备与复核；`dev` 集成须按全局集成租约串行 |
| 同一模块、文件完全互斥 | 有条件并行；R0 显式拆范围，共享测试/配置归一人 |
| 根 POM、parent、模块注册表、构建脚本 | 串行 |
| 接口契约、DTO、错误码、网关路由 | 先 R3 审，再单 owner 串行 |
| Flyway/数据库迁移、数据修复 | 单 owner 串行，版本与顺序由 R0 统一 |
| 任务盘、总 README、记录索引、记忆台账 | R0 独占；执行者通过交接包回报 |
| 同一图表 `.mmd`/`.svg` 或只读分析 | 同一图表串行；只读分析可并行且不得写工作区 |

## 异常处置

| 场景 | 动作 |
| --- | --- |
| 两个任务写同一路径 | 暂停后到任务；拆分范围或改为串行，不得“先写者胜” |
| 多个任务需要合并到 `dev` | 只有一个全局集成租约；按依赖/BE 顺序逐任务集成，禁止并行抢合 |
| 执行者失联或超租约 | 核验提交、工作区和阻塞项；选择续租、改派或回退，保留原成果 |
| 契约/迁移/模块边界冲突 | 冻结相关合并；升级用户或指定决策人；复杂方案先落 `docs/specs/` |
| 证据缺失或命令失败 | 退回 `执行中`；禁止用历史结果、推测或“应该通过”替代 |
| P0 紧急故障 | 冻结并行合并，指定单一写者和唯一 R0；恢复后 24 小时内补卡、记录和台账 |

## 交接包验收模板

```markdown
## BE-xxx 交接验收
- 基线 / 当前 commit：
- worktree / 分支：
- 授权写入范围 / 实际改动：
- 验收命令 / 原始结果：
- 新增或变更测试：
- 未验证项 / 外部依赖 / 已知风险：
- 回滚命令：
- 结论：RECEIVED / RETURNED（原因）
- 下一步：R3 / R4 / R5 / 返工
```

## 禁止

- 禁止未登记任务、未写租约或未指定独立复核者就开工。
- 禁止把 R0、执行者和复核者合并为同一实例/会话来完成并行任务。
- 禁止自行扩大写入范围、清理他人工作区或改动他人私有目录。
- 禁止以“最新代码”替代基线 SHA，以“已验证”替代原始命令结果。
- 禁止 `push -f`、`reset --hard`、整表覆盖或把多个任务合成一个集成提交。
- 禁止在 R5 结论或留痕缺失时自行把任务置为 `已完成`。
