### 1.3 踩坑与处置（重要，复现前务必读）

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 12 个文件在 mermaid-cli 11 下 `Parse error`，10 下全部正常 | v11 对 `activate/deactivate` 嵌套、`&lt;`/`&gt;` 实体转义更严格 | 全量统一用 v10 渲染，保证同一系列风格一致 |
| `Trying to inactivate an inactive participant (X)` | 源文件激活盒嵌套不满足「后进先出」：`deactivate X` 与最近一次 `activate` 不配对 | 对 6 个文件（78/84/90/93/94/95）做**语法归一化**：移除 `activate X`/`deactivate X` 行与箭头上的 `+`/`-` 标记；**参与者、消息文本、顺序一字未改** |
| `Parse error on line 40/52` 且报错指向 `&lt;=now` | `&lt;=` 反转义后形如箭头，被词法器吃掉 | `95` 的 2 处 `&lt;=` 改 `≤`；其余 `&lt;`/`&gt;` 改全角 `＜`/`＞` |
| 归一化后这 5 张图没有激活盒 | `activate` 已移除，只剩默认生命线 | 内容语义完整；恢复激活盒需人工重排，登记 **BE-021** |

> 归一化前后可对比：`git diff` 只出现 `activate`/`deactivate` 行删除与箭头 `+`/`-` 去掉，无任何节点或消息文本改动。

## 2. BE-017：`@Slf4j` 改造

### 2.1 改动

文件：`apex-shared-parent/apex-common/src/main/java/com/apex/scaffold/common/scheduler/VirtualThreadBoundedExecutor.java`

| 前 | 后 |
| --- | --- |
| `import org.slf4j.Logger; import org.slf4j.LoggerFactory;` | `import lombok.extern.slf4j.Slf4j;` |
| `private static final Logger log = LoggerFactory.getLogger(VirtualThreadBoundedExecutor.class);` | 类上 `@Slf4j`（Lombok 生成同名字段 `log`） |

- 保留 `log.error/log.warn` 三处调用，**变量名 `log` 不变**，因此日志字段名、占位符、输出格式全部不变，既有监控/告警规则无需调整。
- 依赖前提已核实：`apex-common/pom.xml` 声明 `lombok`（`provided`）；根 `pom.xml` 的 `maven-compiler-plugin` 已配 `annotationProcessorPaths`（lombok 1.18.36）；同模块 `JsonUtil`/`JwtUtil` 等已使用 `@Slf4j`。
