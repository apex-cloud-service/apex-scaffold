# 缓存与三高能力增强实施计划

**目标：** 在保留现有 DDD 分层、WebFlux 阻塞 I/O 隔离和多级缓存设计的前提下，增强缓存批量操作、缓存击穿/穿透防护、降级快照并发语义，并同步压测脚本、配置文档和测试。

**范围：**
- Redis 缓存批量读写失败语义和输入校验。
- L1 Caffeine 优先的多级缓存批量读取，以及回填行为。
- 降级快照 Redis 写入的原子节流，避免高并发重复提交并允许失败后重试。
- wrk 压测脚本的认证请求体、场景参数和错误配置检查。
- 配置/性能文档和缓存、高并发测试。

**约束：**
- 不改变领域层接口方向，不引入新的外部依赖。
- Redisson 同步调用继续通过 `BlockingIoSchedulers.cache()` 隔离。
- 不对非幂等业务增加自动重试，不记录密码、令牌或完整请求体。
- 生产代码不新增注释，遵循现有格式化规则。

## 任务 1：缓存批量语义

- 为 `CacheServiceImpl.setBatch` 增加失败测试：单项 Redis 写入失败时返回 `false`，并保留其他成功写入。
- 为 `CacheServiceImpl.getBatch` 增加去重、空 key 和单项异常处理测试。
- 实现严格的批量写入结果：只有全部有效项成功才返回 `true`，空/全空 key 返回 `false`。
- 保持所有 Redisson 阻塞操作在线程池中执行。

## 任务 2：多级缓存批量读取

- 为 `MultiLevelCacheService.getBatch` 增加 L1 命中优先、仅对 L1 未命中查询 L2 的测试。
- 保持返回值顺序与输入 key 顺序一致，过滤 null、空值标记和未命中值。
- L2 命中后回填 L1，避免无意义的重复 Redis 访问。

## 任务 3：降级快照并发写入

- 为 `DegradeFallbackService` 增加并发保存快照只提交一次 Redis 写入，以及 Redis 写入失败后下一次允许重试的测试。
- 使用 `ConcurrentHashMap.compute` 或等价原子操作维护写入节流时间，不在 Redis 写入成功前永久阻塞重试。
- 保持本地快照先写、Redis 失败不影响降级读路径的既有语义。

## 任务 4：压测脚本与文档

- 修复 `bench.sh` 登录场景未设置 `wrk.body` 的问题。
- 支持通过环境变量注入测试账号，默认拒绝使用占位密码执行认证压测。
- 增加场景选择和认证请求配置说明，更新 `docs/CONFIGURATION.md` 与 `docs/sales/PERFORMANCE_REPORT.md`。
- 修正脚本对不存在文档路径的引用，指向实际性能报告。

## 任务 5：验证

- 先运行新增定向测试确认按预期失败，再实现并运行至通过。
- 运行相关 Maven 模块测试、`git diff --check`、项目已有格式/质量检查入口。
- 检查变更范围和工作区状态，不提交代码。
