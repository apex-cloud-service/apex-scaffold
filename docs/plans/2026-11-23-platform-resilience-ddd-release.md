# BE-063 分波次实施计划

## 原则

BE-063 与 BE-043/BE-049 保持独立。一次只推进一个可回滚波次；任务盘、共享构建文件、文档索引、记录索引和记忆台账由 R0 串行维护。代码实施及 R5 开始前，R0 必须补齐正式租约、写入范围、禁止触碰、执行者、独立复核者、交接物和验收命令。

## 波次

| 波次 | 范围与交付 | 验证与退出条件 | 回滚 |
| --- | --- | --- | --- |
| A 基线盘点 | 从根 POM 导出模块清单；绘制/核对 DDD 依赖、缓存与韧性设施、配置来源、观测指标及部署发布能力矩阵；登记静态发现和环境限制 | 仅只读审计；逐条附文件/配置/现有测试证据；`bash scripts/governance/verify-docs.sh --strict`、`git diff --check` | 撤销本波新增评审文档，不触碰源码或既有图表 |
| B 领域与共享设施 | 对 DDD 越界、重复策略、缓存一致性与故障策略逐项分级；先处理无需契约/迁移变化且有可复现测试的最小项 | 每项变更先登记独立子范围；固定构建环境运行受影响模块 `mvnd -pl :<artifactIds> -am test` 和 `spotless:check`；后端红线扫描 | 按单项 revert；如有公共契约或持久化影响则暂停并另立规格/任务 |
| C 弹性与容量 | 验证超时、重试、熔断、隔离、限流、背压、缓存失效/击穿及降级的相互作用；采集可重复容量/延迟基线 | 使用明确拓扑、数据规模、并发模型和资源约束；没有压测环境时只交付静态/单测证据并标注未验证 | 单配置项或单模块 revert；恢复原阈值并验证健康状态 |
| D 发布与流量管理 | 核实 Kubernetes 金丝雀/蓝绿、网关灰度、负载均衡、健康门槛、会话状态及回滚脚本；只补已确认缺口 | 可用集群进行分版本切流与回滚演练并留证；无法访问集群则不宣称自动发布能力已验证 | 恢复上一个稳定副本/流量权重；保留数据库向前兼容，未经方案批准不做破坏性迁移 |
| E 报告与独立复核 | 更新文档/脚本/配置说明，执行定向与全量门禁，生成新测试报告，汇总未验证项及逐波次回滚清单 | `mvnd -T4 -B clean verify`（若环境允许）、`bash scripts/test/generate-test-report.sh`、严格治理脚本、独立 R5 对最终 diff 复核 | 按波次撤回；报告保留为历史证据并明确所对应 SHA |
