# 架构设计说明

## 📐 DDD五层架构

Apex Scaffold 采用**领域驱动设计(DDD)**的五层架构模式,确保代码结构清晰、职责分明、易于维护和扩展。

```
┌─────────────────────────────────────────┐
│         apex-interfaces (接口层)         │
│  HTTP端点 | 安全配置 | 过滤器 | 切面      │
└──────────────┬──────────────────────────┘
               │ 调用
┌──────────────▼──────────────────────────┐
│      apex-application (应用层)           │
│  用例编排 | 事务管理 | DTO转换            │
└──────────────┬──────────────────────────┘
               │ 调用
┌──────────────▼──────────────────────────┐
│        apex-domain (领域层)              │
│  聚合根 | 值对象 | 领域服务 | 仓储接口     │
└──────────────┬──────────────────────────┘
               │ 实现
┌──────────────▼──────────────────────────┐
│   apex-infrastructure (基础设施层)        │
│  持久化 | 缓存 | 消息队列 | 外部服务       │
└──────────────┬──────────────────────────┘
               │ 依赖
┌──────────────▼──────────────────────────┐
│        apex-common (公共模块)            │
│  工具类 | 异常 | 统一响应 | 常量          │
└─────────────────────────────────────────┘
```

### 分层职责

#### apex-common (公共模块)
- **无业务依赖**，可被其他模块自由引用
- 提供通用工具类、异常体系、统一响应格式
- 定义系统常量和枚举

#### apex-domain (领域层)
- **核心业务逻辑**，不依赖任何上层模块
- 定义聚合根、值对象、领域服务
- 定义仓储接口（由基础设施层实现）

#### apex-application (应用层)
- **用例编排**，协调领域对象完成业务用例
- 处理事务边界
- DTO 与领域对象的转换

#### apex-infrastructure (基础设施层)
- **技术实现**，实现领域层定义的接口
- 数据持久化（MyBatis-Plus）
- 缓存、消息队列、外部服务集成
- 提供通用的基础设施组件（缓存、限流、熔断等）

#### apex-interfaces (接口层)
- **协议适配**，将 HTTP 请求转换为应用层调用
- 安全配置（JWT、CORS、Spring Security）
- WebFlux 过滤器链
- AOP 切面（日志、限流、防重放等）
- 全局异常处理

## 核心组件

### 1. 统一响应格式 (Result<T>)

所有 API 接口返回统一的响应格式：

```json
{
  "code": 0,
  "msg": "成功",
  "data": {...},
  "traceId": "abc123"
}
```

### 2. 全局异常处理

通过 `GlobalExceptionHandler` 统一捕获和处理异常，返回标准化的错误响应。

### 3. 多级缓存

- **L1**: Caffeine 本地缓存（进程内）
- **L2**: Redis 分布式缓存
- 支持缓存穿透防护、雪崩防护、布隆过滤器

### 4. 限流熔断

- **Sentinel**: 入口限流、热点参数限流
- **Resilience4j**: 熔断器、重试策略
- 三级容错保障系统稳定性

### 5. 消息队列

- RocketMQ 生产者/消费者封装
- 幂等消费保证
- 发件箱模式可靠投递

### 6. 文件存储抽象

策略模式支持多种存储后端：
- Local (本地文件系统)
- MinIO (对象存储)
- S3 兼容存储

### 7. 监控告警

- **Prometheus**: 采集应用指标
- **Grafana**: 可视化看板
- **Alertmanager**: 告警规则配置

## 安全机制

- JWT Access Token + Refresh Token
- RBAC 基于角色的权限控制
- CORS 跨域配置
- SQL 注入防护（参数化查询）
- XSS 防护（输入验证）
- 防重放攻击（@AntiReplay 注解）
- 并发控制（@ConcurrencyControl 注解）

## 扩展指南

### 添加新的业务模块

1. 在 `apex-domain` 中定义聚合根和仓储接口
2. 在 `apex-infrastructure` 中实现仓储（Mapper + PO + Converter）
3. 在 `apex-application` 中编写应用服务
4. 在 `apex-interfaces` 中创建 Handler 和路由

### 添加新的基础设施组件

1. 在 `apex-infrastructure` 中创建新包
2. 定义接口和实现
3. 通过 Spring 自动配置暴露给应用层使用

### 自定义配置

所有配置项都在 `application.yml` 中，支持通过环境变量覆盖。
