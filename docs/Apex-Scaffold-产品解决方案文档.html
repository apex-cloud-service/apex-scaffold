01产品概述与定位

Apex Scaffold 是一套面向中小企业输出的企业级 Java 后端平台底座。它不是单一业务系统，而是 「平台底座 + 可插拔业务域」的组合：开箱提供认证、RBAC 权限、系统管理、工作流、办公集成（钉钉/飞书/企业微信）、 文件服务、任务调度与数据脱敏等能力，业务方在其上快速搭建自己的 SaaS / 企业内部系统。

当前运行形态为 「1 个 API 网关 + 5 个业务微服务 + 2 个增强服务（任务代理、可选脱敏）」，所有请求经网关统一进出， 前端（管理后台，独立仓库/镜像）通过网关访问，不直连业务服务。

1.1 核心卖点（产品语言）

  • 企业级安全内建：JWT 非对称验签、MFA（TOTP/短信/邮箱/备份码）、OAuth2 授权服务器、SSO、IP 黑白名单、防重放、幂等、操作审计，开箱即用。
  • 权限三层模型：功能权限（RBAC）+ 数据权限（5 档数据范围）+ 租户隔离（行级自动过滤），支撑多租户 SaaS 交付。
  • 办公生态连接器：钉钉、飞书、企业微信三平台统一适配（组织同步 / 消息 / 审批 / 日历 / 文档），含自研站内信（HTTP 收件箱 + WebSocket 在线提醒）。
  • 高可用工程底座：限流、熔断、Outbox 最终一致、优雅停机、灰度发布、多级缓存、五后端对象存储，全部以配置开关交付。

03各端与子系统全景

3.1 端（客户端触点）清单

端形态说明

05功能清单（按子系统）

5.1 认证中心（apex-auth）—— 信任与凭证

7.4 安全基线（安全相关产品红线）

  • 密钥强校验前置：5 个密钥（数据/安全/配置加密、JWT）不合规即拒绝启动，禁止模板值。
  • 身份头防伪造：网关无条件剥离客户端 X-User-Id / X-Tenant-Id 等，身份只来自验签后的 JWT。
  • 内部接口公网 403；CORS 网关唯一收敛（生产白名单必填）；Redis 生产强制密码。
  • 审计三线并行：操作审计（@OperationLog）、登录日志、认证审计，配合 API 调用日志与安全指标。

08产品视角的空白点与设计建议

以下为代码实盘确认的「能力缺口 / 待设计点」，是产品设计时最值得关注的地方：

#空白点现状产品建议
1租户管理（Tenant CRUD）租户模型与配额字段齐备（套餐/到期/用户数/存储配额/状态机），但无任何管理端点建议优先设计「租户生命周期管理 + 套餐配额管控」模块。
2工作流定义/设计器引擎具备实例/任务/干预能力，定义仅服务层可建，无建模端点与设计器补齐流程定义 CRUD、版本管理、可视化设计器与部署审核；是办公审批可售化的前提。
3密码找回 / 重置有密码策略配置，未见自助 reset-password 端点设计「短信/邮箱验证码找回」闭环，与既有创蓝短信通道和 MFA 备份码体系衔接。
4邮件通道全仓无邮件集成通知渠道矩阵（站内信/SMS 已有）补 Email；可复用消息模板 + Outbox 可靠投递。
5文件分享无分享端点；安全模型为令牌 + 归属校验设计带有效期/提取码的分享链接（区别于预签名 URL），注意 Local 后端不发无认证签名。
6双 RBAC 体验割裂主应用 RBAC 与认证中心 RBAC 角色码体系不同、无统一管理界面设计「统一权限中心」或明确双体系适用边界，避免管理员困惑；已有 permission:sync 配置入口可作起点。
7菜单种子冲突菜单 id=2000 在 V33/V38 两个迁移中被赋予不同语义（办公平台 vs 数据管理）前端菜单设计以最终形态为准并做一次种子收敛，避免升级歧义。
8站内信单实例状态WS 票据/连接注册表为单实例内存态，多实例需粘性路由，无跨实例实时广播（仅未读 HTTP 补偿）产品侧明确 SLA：断线补偿语义已定义；如需横向扩展体验升级需排期（粘性会话或网关会话保持）。
9认证中心 i18n 缺位主应用已支持 4 语言（zh_CN/zh_TW/en_US/th_TH），认证中心错误消息为硬编码中文出海/多语言场景需列入改造项。
10前端仓库缺位管理后台前端为独立镜像，源码不在本仓库（Vue3 独立立项中）本文档的角色/菜单/权限码清单可直接作为前端权限指令与路由守卫的设计输入。
建议的优先级（供评审讨论） P0：租户管理（1）+ 工作流设计器（2）——直接影响产品可售性； P1：密码找回（3）+ 统一权限中心（6）——体验与安全闭环； P2：邮件（4）、文件分享（5）、i18n 补齐（9）——渠道与合规增强。

9.1 术语表

术语说明
TokenPair访问令牌（ACCESS，2 小时）+ 刷新令牌（REFRESH，7 天），RS256 非对称签名，刷新一次性轮换。
RBAC基于角色的访问控制：用户→角色→权限码；管理接口叠加管理角色硬校验。
DataScope数据权限：ALL / 本部门 / 本部门及以下 / 仅本人 / 自定义，SQL 自动改写。
Tenant 隔离行级隔离：MyBatis 拦截器自动注入 tenant_id；租户身份来自 JWT，请求头不可伪造。
Outbox本地消息表模式：业务写入与事件记录同事务，后台扫描投递 MQ，保证最终一致。
Single-Flight并发回源合并：同一 key 的并发请求只放行一个回源，其余共享结果，防缓存击穿。
灰度路由请求头强制 > 租户白名单 > 用户尾号百分比三级判定，配合实例 gray-tag 标签分流。
Result<T>统一响应结构 {code, msg, data, traceId}；业务成功码为 0（≠HTTP 200）。
