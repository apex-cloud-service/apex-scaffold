### 二、统一版本号

#### 2.1 任务目标

修复 README.md 中的版本号不一致问题，确保项目版本号统一为 1.2.0。

#### 2.2 实施过程

1. **问题发现**
   - 原检查脚本从根 POM 提取的是 Spring Boot 版本号（3.5.15）而非项目版本号
   - README.md 中的版本号实际已经正确（1.2.0）

2. **修复检查脚本**
   - 修改版本号提取逻辑，跳过 `<parent>` 部分
   - 只检查 README.md 徽章中的项目版本号
   - 不再误报其他技术栈的版本号（JDK、Vue、Vite等）

3. **验证结果**
   - 项目版本号：1.2.0 ✅
   - README.md 徽章版本号：1.2.0 ✅
   - 版本号一致性检查通过 ✅

#### 2.3 修改文件

**文件**: [scripts/ci/check-doc-consistency.sh](file:///Users/work/apex-scaffold/scripts/ci/check-doc-consistency.sh)

**关键修改**:

```bash
# 修复前：提取第一个 <version> 标签（错误地获取了 Spring Boot 版本号）
PROJECT_VERSION=$(grep -m 1 '<version>' pom.xml | sed 's/.*<version>\(.*\)<\/version>.*/\1/')

# 修复后：跳过 parent 部分，提取项目版本号
PROJECT_VERSION=$(awk '/<parent>/,/<\/parent>/{next} /<version>/{print; exit}' pom.xml | sed 's/.*<version>\(.*\)<\/version>.*/\1/')

# 只检查 README.md 徽章中的项目版本号
README_PROJECT_VERSION=$(grep -m 1 'Apex_Scaffold-v' README.md | grep -oE 'v[0-9]+\.[0-9]+\.[0-9]+' | sed 's/v//')
```

#### 2.4 价值

- ✅ **准确的版本检查**: 正确识别项目版本号
- ✅ **减少误报**: 不再将技术栈版本号误认为不一致
- ✅ **CI 质量保障**: 自动化验证版本号一致性

### 四、规范化 Flyway 迁移脚本命名

#### 4.1 任务目标

规范化 Flyway 迁移脚本命名格式，统一为 `V数字__描述.sql` 格式。

#### 4.2 实施过程

1. **问题发现**
   - 原检查脚本正则表达式过于严格：`^V[0-9]+__[a-z_]+\.sql$`
   - 不允许描述部分包含大写字母和数字
   - 导致 `V25__oauth2_authorization_server_schema.sql` 被误报

2. **修复检查脚本**
   - 放宽正则表达式：`^V[0-9]+__[a-zA-Z0-9_]+\.sql$`
   - 允许描述部分包含大小写字母、数字和下划线
   - 更符合实际命名规范

3. **验证结果**
   - 所有 Flyway 迁移脚本命名规范检查通过 ✅
   - 22 个迁移脚本全部符合规范

#### 4.3 修改文件

**文件**: [scripts/ci/check-doc-consistency.sh](file:///Users/work/apex-scaffold/scripts/ci/check-doc-consistency.sh)

**关键修改**:

```bash
# 修复前：只允许小写字母和下划线
if ! echo "${basename}" | grep -qE '^V[0-9]+__[a-z_]+\.sql$'; then

# 修复后：允许大小写字母、数字和下划线
if ! echo "${basename}" | grep -qE '^V[0-9]+__[a-zA-Z0-9_]+\.sql$'; then
```
